1. MINUS BUTTON POSITIONS ARE REVERSED (ACTIVE BUG)
   The minus buttons on the Captain Creation screen are rendering in the
   WRONG positions - they appear where plus buttons should be or vice versa.
   
   The original code loaded minus button assets from captaincreation.dat 
   (Allegro 4 datafile). During Phase 1 (datafile removal), a previous 
   subagent session set the minus button bitmaps to NULL because the assets
   weren't extracted from the .dat file. This session:
   - Generated minus button BMPs from plus button BMPs (tools/create_minus_btn.py)
   - Updated ModuleCaptainCreation.cpp to load them
   - BUT the user reports the positions are reversed/swapped
   
   ACTION NEEDED: Look at ModuleCaptainCreation.cpp around lines 348-363 
   where m_minusBtns[] are created. The X positions use PLUS_*_X + 42 offset.
   Compare with how m_plusBtn is drawn (around line 502-509) and how 
   m_minusBtns are drawn (around line 531). The plus and minus button 
   positions may have been swapped during conversion, OR the generated 
   minus button images may look like plus buttons (the image generation 
   script may not have worked correctly). Check both.

2. ORIGINAL CRASH - NULL BITMAP IN Button::PtInBtn (FIXED)
   Thread 5 crashed in al_get_bitmap_width called from Button::PtInBtn 
   because m_minusBtns had NULL imgNormal bitmaps. Fixed by:
   - Adding null guards in Button::PtInBtn, Button::OnMouseMove, 
     Button::OnMouseReleased (src/Button.cpp)
   - These guards should stay even after fixing the asset loading

3. MOUSE TRAILS (FIXED THIS SESSION)
   Added al_clear_to_color(al_map_rgb(0,0,0)) on m_backbuffer at the 
   start of each frame in Game::RunGame() (around line 1168).

4. MOUSE COORDINATE SCALING (FIXED PRIOR SESSION)
   Mouse coords from Allegro 5 arrive in display-space. They're scaled 
   to 1024x768 internal space in Game::UpdateMouse() using screen_scaling.
